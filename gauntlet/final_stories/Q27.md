# Q27 - Tell me about a time when you exceeded expectations.
**LP:** Deliver Results (primary); Insist on the Highest Standards.   **Story:** STORY 6 - the 4-signal PCB-vs-layout comparison engine; VLM kept server-only per STORY 8 anchors; engine numbers = canonical STORY 6 set.

## Core Answer

The tool compared a photographed PCB against its layout design. (PCB = the green circuit board inside electronic devices; the layout design = the drawing the board is built from.) The ask was simple: flag where the board doesn't match. My first version met it literally - grayscale both images (convert them to plain shades of black-and-white brightness), subtract, flag the differences. It caught the obvious defects, and on real boards it cried wolf about 15 percent of the time - almost all false alarms from lighting and sensor noise. (A "false positive" or "false alarm" = the tool points at a spot and calls it bad when the board there is actually fine. "Sensor noise" = random graininess from the camera.) Technically done. Useless on the floor: one bad flag in seven and engineers stop trusting the report and check everything by hand. Then the tool saves nothing.

So I set my own bar: cut the false alarms without losing real catches, and prove it on images where I knew the answer. Nobody asked me to. That gap is the expectation I exceeded.

I rebuilt the comparison as four signals, each one seeing what the others miss. (A "signal" here = one independent way of testing the two pictures against each other, like a different pair of glasses; the "4-signal engine" is just the name for the combination of four of these tests.) Raw grayscale difference catches gross mismatches. CLAHE normalizes local contrast (an automatic brightness-equalizer applied patch-by-patch over the image), so lighting stops registering as a defect and a wrong-value resistor starts to show. A histogram stretch exaggerates near-identical parts (it stretches the spread of light-vs-dark values apart so nearly-identical parts look visibly different). Canny edge maps are immune to brightness - my strongest signal for structural differences like a missing component. (An "edge map" = a black-and-white outline of every shape in the photo; outlines don't change when the lighting does.) Each signal votes; the votes combine into a weighted score (more trustworthy signals' votes count for more), and I left the threshold on a slider (a dial the engineer turns to decide how eager the tool is to cry "mismatch") because the engineer knows the board and I didn't.

Then the hard part: proving it. I built a ground-truth set - a hundred board images with known wrong, missing, and extra components - (a "ground-truth set" = a test collection where the right answers are already written down, so every flag the tool gives can be checked against a known fact) and grid-searched the signal weights against precision and recall (grid search = trying every combination of weights and keeping the best-scoring one; precision = when the tool flags something, how often it's really a defect - not crying wolf; recall = of the real defects, how many it caught - not missing any). False alarms went from about 15 percent to under 3, true catches stayed above 95 ("true catch" / true positive = a real defect the tool did catch), and the best threshold scored an F1 of 0.94. (F1 = one accuracy number that balances not-missing-a-real-defect against not-crying-wolf; 1.0 is perfect.)

I did consider generative AI for the detection itself - the server build of the tool uses a GPT-4o VLM to read mismatch reports. (VLM = vision-language model, an AI that can look at a picture and read it like a person.) But the factory tool ran offline on locked-down machines, and a detector that isn't reproducible can't be audited when a board gets rejected. ("Reproducible" = gives the identical answer every time on the same input; a read-the-picture AI can answer differently on a re-run, so you can't prove why a board was failed.) So the model stayed server-side, where it helps a human read, and the detection stayed classical CV (ordinary image-processing math, not AI - same input, same output, every time).

Two corrections. A fifth signal - frequency-domain via FFT - added compute and no accuracy, so I cut it. (FFT = a transform that views the image as repeating patterns and textures instead of pixels - a different pair of glasses, but it bought nothing here.) And I'd have started from the edge detection instead of the raw difference; that spent my early iterations fixing false alarms I never needed to own.

The ask was a comparison that works. I shipped one the engineers trusted, and the false-alarm rate is the evidence.

## Memory Anchors
- Problem: Board-vs-layout comparison cried wolf ~15% of the time -> engineers re-checked everything -> tool saved nothing. (~15% = share of flags raised on boards that were actually fine.)
- Customer: PCB manufacturing engineers on a restricted-network factory floor (suite built solo).
- Insight: The ask was "works"; the actual requirement was "trusted" - false-alarm rate is the business metric.
- Action (mine): Four-signal voting comparison (raw / CLAHE / contrast-stretch / Canny edges); self-built 100-board ground-truth set (test images with the right answers already known); grid-searched weights; threshold left as engineer's slider; VLM kept server-side only.
- Result: False positives ~15% -> <3% at true positives >95% (false positive = flagging a good spot; true positive = catching a real defect); F1 0.94 (P 0.97 / R 0.91) on the 100-board set (P = precision = ~97 of every 100 flags are real problems; R = recall = ~91 of every 100 real problems caught; F1 = the one score balancing both).
- Learning: More signals != better (FFT cut); start from the most robust signal (edges), not the easiest.
