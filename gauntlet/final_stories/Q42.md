# Q42 - tell me about a time where you received critical feedback, how did you implement it?

**LP:** Earn Trust (primary - took "your feature silently dies" seriously and chased it); Learn and Be Curious (the model/provider differences behind one bug report); Deliver Results (the command layer works across both backends)   **Story:** Tab Scroller - the "AI commands silently do nothing" feedback, traced to markdown-fenced and prose-wrapped JSON from the model, and the contract + tolerant-parser + explicit-failure fix I implemented (AI_WORKSPACE_FIX.js:72-128; background.js:1520); distinct from Q35 (same extension, comfort-zone spine) and Q91 (critical feedback on the BOM parser)

## Core Answer

The feedback on my Chrome extension was one line: "your AI commands silently do nothing sometimes." Tab Scroller is my personal extension - a searchable strip of all your open tabs - and typed commands like "group my research tabs" have an AI model pick which tabs the action applies to. [PARTIAL - the fix file records the failure and the repair; the session where the complaint came in isn't in the record, and I won't quote a person]

Silent was the worst kind of report: nothing to point at, nothing to reproduce. So I chased it through the plumbing. The AI's answer to my program has to be machine-readable: a small JSON object - a strict text format my code parses into tab numbers. The calls failed when the model answered correctly but not cleanly: it wrapped its JSON in markdown code fences - the backtick marks chat interfaces use for code - or prefixed a "Sure, here you go" sentence. The parser threw on the extra characters, and the old error handling swallowed it. The command just stopped. The feature wasn't broken; my plumbing called a good answer garbage because of its wrapping paper.

I implemented the feedback in three layers. First, tighten the contract: the instruction now states the exact shape, with examples and an empty-list rule, and the call requests a JSON response type from providers that support it - format as a property of the request, not a hope. Second, make the reader forgiving: trim the answer, strip a leading or trailing code fence, and if JSON is still buried in text, extract the outermost curly-brace object and parse that - with the model's temperature, its creativity dial, turned down. Third, make silence speak: a missing answer now says "the AI did not respond" instead of vanishing, and the same JSON-only reminder went into the local, on-my-machine model's prompt path, which had the same disease.

The judgment I'd defend: no single layer is trusted alone. The contract reduces messiness, the tolerant parser absorbs what survives it, and the explicit failure keeps the user informed when both give out. Any one of the three alone would have halved the bug and kept the mystery.

What stuck: whenever a probabilistic system - one that answers differently each time - feeds my code: contract shape, forgiving reader, loud failure. Never again a swallowed error in a user-triggered action.

## Memory Anchors
- Problem: "AI commands silently do nothing" - model returned correct JSON wrapped in markdown fences or prose; JSON.parse threw; error handling swallowed it; dead buttons, no signal
- Customer: extension users (me first); silence was worse than an error because nothing was actionable
- Insight: the answer was right and the reading was rigid - the bug sat at the boundary between a probabilistic writer and a strict parser
- Action (mine): rewrote the instruction to an exact JSON contract with examples + empty-list rule + requested JSON response type; fence-strip + embedded-object extraction before parse; low temperature; explicit "AI did not respond" path; same JSON-only reminder for the local model path
- Result: commands parse across wrapped and bare answers on both hosted and local backends; failures surface visibly - behavioral verification on known-answer commands; no error-rate metric exists [PARTIAL]
- Learning: contract + tolerant reader + loud failure is the full fix for AI-output plumbing; silent catch blocks are half of every "does nothing" bug report
