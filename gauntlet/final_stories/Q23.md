# Q23 - tell me about a time where you took work outside your responsibility

**LP:** Ownership (primary; touches Deliver Results, Learn and Be Curious)   **Story:** AMAZON_INTERVIEW_PREPARATION.md STORY 9 - the training-data collector, BGSW PCB inspection suite (solo build)

## Core Answer

Is about the half of the job that nobody wrote down.

I was the sole builder of the PCB inspection suite - the comparison engine and the defect classifier. (A PCB is the green circuit board inside almost every electronic device. The comparison engine is the part that photographs a finished board and finds where it differs from its design file; the defect classifier is a small AI that sorts each problem into a type - wrong part, backwards, missing.) The classifier was blocked on training data: about two thousand component images, none of them labeled. ("Training data" is the set of examples a model learns from; "labeling" means a person writing the correct answer on each image - "good" or which defect - so the model can go through *training*, the process of showing it enough examples that it learns the pattern on its own.) Building the tool to label them was part of my task. What was not part of anyone's task was making sure the labels could be trusted.

So, the tool first. A small Tkinter window (Tkinter is the plain pop-up-window toolkit that ships with the Python language - nothing extra to install): one image, a status bar, and the keyboard. G for good, one through four for the defect types, and it auto-advanced to the next image. A skip key, because an image too blurry to judge should not enter the dataset with a guessed label - skips went to a separate file for later. Sessions were resumable (close it and pick up exactly where you stopped), and the CSV output (CSV is just a plain-text spreadsheet, one row per image) matched the format the training pipeline already read (the software that runs the model's training already expected that file shape), so there was no conversion step. That took labeling from about thirty seconds an image to about three.

Then the part I'd actually call ownership. The task said label fast. It said nothing about trusting the result, and a dataset nobody checks quietly decides how good your model can be. So I labeled the entire set again, a week later, without looking at my first answers, and compared them. I agreed with myself 92 percent. (That number counts one thing only: how often my second, blind pass gave the same label as my first pass - a check that I'm consistent with myself, not proof the labels are right; it came from comparing my own two passes row by row, not any external test.) The eight percent were borderline, and I re-examined every one and picked the primary defect (when a part had more than one problem, the single main one to record), instead of leaving a coin-flip label to train on. I also plotted learning curves while training (a graph of how accurate the model got as it saw more images, which shows the point where extra data stops helping), which gave me a number for when to stop collecting data - the return was flattening, so I closed that round instead of chasing it.

What I took from it: the tool was the easy half, and believing its output is the job. And I assumed a mouse would feel more intuitive - it does, until you're on image five hundred. Keys won, and next time I'd add batch labeling for near-identical crops (batch labeling = labeling a whole group of look-alike images in one action; a "crop" is the cut-out close-up picture of a single part).

## Memory Anchors
- Problem: classifier blocked on ~2,000 unlabeled crops; tool was my task, label trust was nobody's
- Customer: the training pipeline waiting on data - and downstream, engineers trusting the suite's verdict
- Insight: "label fast" was the task; "trust the labels" was the responsibility
- Action (mine): built the Tkinter collector; did all 2,000 labels myself; re-labeled the full set a week later, blind; re-adjudicated every disagreement
- Result: ~30s -> ~3s/image; 92% self-agreement, 8% resolved
- Learning: a tool isn't the outcome - trustworthy data is; keyboard beats mouse at volume; batch labeling was the missing feature

## Follow-Up Bank
1. Was any of this actually outside your responsibility? - The labeling tool itself was on my task list, and I won't claim otherwise. The unassigned half was the trust: no one's task said verify the labels or decide when to stop collecting, and I took both.  [SAFE]
2. Why Tkinter, not a web tool? - Simplest thing that worked: ships with Python, no local server, no browser-compat work. UI polish was the trade-off, and it's fine for a one-person internal tool.  [SAFE]
3. How were the 30s and 3s measured? - 30s was my own stopwatch pass over a handful of images in the spreadsheet flow before I wrote the tool; the ~3s comes from timestamps in the tool's session CSVs. Rough personal timings, not instrumented throughput - the 30s->3s is the per-image speedup, and the ~10h manual figure was its own back-of-envelope I wrote down before building, not that baseline multiplied by 2,000 (that lands near 17h), so call the manual case somewhere around 10-17 hours by my rough estimate. Put the figures plainly: ~30s and ~3s are seconds *per image*, ~10-17 hours is my rough total for doing the whole ~2,000-image set the slow by-hand way, and by the same arithmetic the tool's ~3s over ~2,000 images is on the order of ~100 minutes for the whole set - a derived total from those two numbers, not a single stopwatch run I timed.  [PARTIAL - self-timed, not a study]
4. What does 92% agreement actually prove? - It measures label stability, not correctness (in plain words, "stability" means I'd give the same answer a second time, not that the answer is truly right): same person (me), a week apart, blind to the first pass, compared row-by-row. A consistent bias would survive it. A second labeler would have been the stronger check; there wasn't one on a solo project. The 8% disagreements were borderline and each was re-examined and assigned the primary defect.  [PARTIAL - honest limit]
5. Two defects on one image? - One label per image forces a primary-defect decision - a simplification, since a real component can have both. Genuinely ambiguous ones went to the skip file instead of a guessed label.  [SAFE]
6. Why CSV, not JSON? - Labels are flat: filename, label, timestamp, one row per image. CSV is simpler to write and inspect in Excel; JSON only pays if labels are nested. (In plain terms: CSV is a flat spreadsheet-style file, one row per item; JSON is a nested format meant for programmers - overkill here.)  [SAFE]
7. What did the learning curves say? - 2,000 images put the model at 94% (94% is the share of test images the model gets right, judged on examples it never trained on); doubling to about 4,000 was estimated at roughly 96%, marginal beyond - the number that said stop collecting.  [PARTIAL - curve-based estimate, not a measured sweep]
8. What would you improve? - Batch labeling for near-identical crops (a "crop" is the cut-out close-up picture of a single part): many images were the same component at slightly different angles, so a "label all similar" pass would cut the remaining time further.  [SAFE]
9. Hardest part? - Not the code. The grind: the whole set twice, then re-adjudicating roughly 160 borderline images (re-adjudicating = going back and deciding each one's label again) (~8% of 2,000, arithmetic not telemetry) without just confirming my own first guess.  [PARTIAL - 160 is derived]
10. Was there disagreement with anyone? - Solo builder, so no documented pushback to claim. The real disagreement was with my own first-pass labels on the borderline set.  [GAP - do not invent stakeholder conflict]
11. At larger scale, what breaks? - Self-agreement is the wrong audit with multiple annotators; I'd need inter-annotator agreement on a shared sample plus an adjudication rule before a second person touches the set. (Plain terms: "self-agreement" is whether I match my own earlier answers; "inter-annotator agreement" is whether two *different* people label the same images alike; an "adjudication rule" is a preset way to settle it when they don't.)  [SAFE - framed as what I'd do, not what happened]
