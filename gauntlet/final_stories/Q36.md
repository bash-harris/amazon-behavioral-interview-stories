# Q36 - a time when you had to compromise quality over a prescribed timeline

**LP:** Bias for Action (primary); Deliver Results; Insist on the Highest Standards.   **Story:** BGSW PCB Inspector Suite - the copied-fork shortcut: tool two cloned from tool one to hit a this-week date, six months of divergence, and the designed-but-not-done collapse plan (`BAR_RAISER_TECHNICAL_PREP.md` :227, :346; migration design :307-311). Reframed from Q13: the core there is the bounded five-day prototype that was repaid; the core here is the compromise that is *still being repaid* - the honest one.

## Core Answer

Yes. And the example that really tests this question isn't the prototype where I paid the debt back fast - it's the copy that cost me six months. (The prototype was the first tool's quick five-day build, finished properly within two weeks - the shortcut that got repaid. This one hasn't been yet.)

I had one PCB inspection tool built. A PCB is the green circuit board inside every electronic device. The manufacturing side needed a second one, with different inputs but the same comparison core - the check that compares a photo of a finished board against the board's design file and flags what looks off - and the timeline was fixed: working that week. The clean path was to factor the shared logic out - rewrite the code so both tools ran on one shared copy instead of two - and build tool two on top of it, and that plainly took longer than my week. So I did the smaller thing: I copied the first tool's code, changed the parts the new tool needed, and it worked on schedule.

The quality I gave up, stated exactly: a copy is never free. I now had two codebases answering the same question, and they drifted - each copy picked up small edits over time, so slowly the two became different. The worst concrete drift was that they grew two different anomaly formulas - different scoring logic, meaning two different versions of the rule that decides whether a flagged spot on a board is a real defect or just noise - so the two tools could look at the same board and disagree about whether a part was wrong. Same board, two answers. That's not a bug. That's two standards.

And I own the second half: I let it run for six months before I treated the divergence as debt with a due date. (That "six months" = the span from making the copy to finally calling it debt - it comes from my own prep notes, a documented recollection, not an instrumented measurement, so I say "about.") The rule I keep from it now is that a copy is only acceptable if you give it a merge-back deadline the day you make it - merge-back meaning a date by which the copy gets folded back into one shared codebase. I didn't give this one a date.

There's a collapse plan now, and I won't say it's finished. First a golden-output harness - record what each tool says today on a fixed input set: a standard batch of test cases whose current answers get saved as the reference, so any later change that moves an answer shows up. Then extract the shared scoring core - one copy of the deciding logic both tools use - without changing behavior, prove the outputs come out byte-identical, meaning every saved answer matches exactly as before, and only then fix the formula disagreement, with the harness watching so the change is visible. Designed and tracked; not done.

The trade in one line: I bought a week and paid about six months of drift, and the fix is now harder than the refactor I skipped - the refactor being that restructure where both tools would have shared one copy of the logic. What didn't move is the standard - the bar is one source of truth, and I'm tracking the gap to it.

## Memory Anchors
- Problem: second PCB inspection tool demanded, working that week; shared-logic refactor wouldn't fit the week.
- Customer: the manufacturing engineers needing consistent verdicts across both tools.
- Insight: a copy is debt, not a resting state - it's only safe with a merge-back deadline set the day you make it.
- Action (mine): shipped tool two by copying tool one; let the copies drift ~six months (two different anomaly formulas); later defined the collapse: golden-output harness -> behavior-preserving extraction of a shared scoring core -> byte-identical proof -> then the formula fix under test.
- Result: deadline met that week; cost was ~six months of divergence and same-board disagreement risk; repayment designed and tracked, not done - stated that way.
- Learning: name the price of a shortcut before you take it, and put a date on it; a dated shortcut collapses, an undated one compounds.
