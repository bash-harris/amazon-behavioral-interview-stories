# Q8 — tell me about time where you completed a project on your own

**Mapped LP(s):** Think Big (primary); touches Ownership and Deliver Results.

**Story used:** A genuinely completed solo project — shipping the entire PCB inspection suite as one standalone HTML file with no server (`AMAZON_INTERVIEW_PREPARATION.md` STORY 4, "The Standalone HTML That Replaced a Server", plus STORY 15, "Compiling a Full Stack into a Single File", which automates the same build). ## Answer (core, ~480 words)

The project I completed on my own was making the whole PCB inspection suite run with no server at all — one HTML file you open by double-clicking, fully offline.

The tools had started out on a Flask backend. But the people who used them sit at factory-floor machines with no internet, no ability to install software, and limited IT support. Getting Python installed and network access configured was more than the team could take on, and every deployment was a support ticket. I was the only engineer on the suite, and I decided the server had to go. The direction was deliberate: instead of deploying a web app, ship the entire thing as one self-contained file. BOM parsing, CAD alignment, ML inference — all of it had to live inside one HTML document with no network.

I started by auditing what had to travel with the file. OpenCV.js was about 8MB, TensorFlow.js about 3MB, PDF.js about 1MB, and XLSX.js about 500KB — roughly 12.5MB of libraries, none of which could come from a CDN. I wrote `compile_tool.py` to do the bundling: it collects the HTML, CSS, and JS, inlines them in dependency order, base64-encodes the binary libraries, resolves relative paths, and stamps a version identifier into the title. The hard part was OpenCV.js — it's a WebAssembly module that normally fetches a separate `.wasm` file. I embedded the WASM binary as a base64 data URL and changed the loader to decode it at runtime, because `WebAssembly.instantiate` accepts an `ArrayBuffer` directly. TensorFlow.js inlined cleanly, and I embedded the model weights as a JavaScript constant. Auto-save changed too: the server wrote to the filesystem, so I moved it to `localStorage`, with a 5MB quota check that warns the user and garbage-collects old inspections.

The compile step showed the value. My first builds were manual — concatenating by hand — taking about 30 minutes each and breaking roughly one time in five when I got the file order wrong. After `compile_tool.py`, the same build took 8 seconds with zero errors.

The finished file was about 25MB — large, but it fit on email or a USB stick. It loaded in about 5 seconds on a factory-floor machine, versus about 2 seconds on the server version, and everything worked identically: BOM parsing, layout comparison, image alignment, ML inference, and auto-save. I distributed it by email and USB drive. Engineers could now run the full suite by double-clicking one file — no Python, no network configuration, no IT ticket. The project was complete, and it was in people's hands.

Looking back, I'd compress the embedded libraries more aggressively — 25MB runs into 20MB email limits, and gzip could have brought it near 15MB. I also assumed modern browsers; a few machines still had IE11, which can't run WebAssembly, so I added a compatibility check rather than a rewrite. The bigger lesson was architectural: I should have designed for standalone from the start rather than retrofitting it out of a server build.

## Deep follow-ups (likely bar-raiser probes)

**Q: Why embed everything as one file instead of shipping separate files?**
**A:** Single-file distribution removes a failure mode. If the tools needed separate files, the engineers would have to keep them in the same directory, and accidentally moving just the HTML would break it. Base64 adds about 33% overhead, but the convenience is worth the size.

**Q: How does OpenCV.js load if it's a WebAssembly module?**
**A:** Normally the loader fetches a separate `.wasm` file. I replaced that fetch with a data URL containing the base64-encoded WASM binary. The browser decodes it into an `ArrayBuffer`, and `WebAssembly.instantiate` takes the buffer directly — no network needed.

**Q: What happens when localStorage fills up?**
**A:** Every write is wrapped in try-catch. On a `QuotaExceededError` I warn the user and suggest clearing old inspections. I also added simple GC: after an inspection, if total usage exceeds 4MB, the tool removes the oldest entries, so the 5MB limit isn't hit in normal use.

**Q: Why not IndexedDB?**
**A:** IndexedDB has a far larger quota and structured data, but it's asynchronous, which complicates auto-save. Synchronous `localStorage` is simpler to reason about for the few KB per inspection. If the data grew, I'd switch.

**Q: Why Python instead of a bundler like Webpack?**
**A:** The logic is straightforward string manipulation — no module bundling, minification, or source maps needed. `compile_tool.py` is about 200 lines. Webpack's config and learning curve aren't justified for a build step that runs once before deployment.

**Q: How did you know the standalone build matched the server?**
**A:** A test harness ran the same 15 BOM files and 10 board images through both versions and compared outputs: reconciliation reports had to match exactly, alignment within 1 pixel, ML classifications identical. I ran it after every compilation.
