## Answer (core, ~430 words)

I'll give you the one case I can stand behind, and I'll be precise about where the line is.

The direction I had to work within was the pin-count rule in the BOM reconciliation tool. The tool compared the pin count in the BOM against the number of pads in the layout footprint, literally. If the BOM called a part an 8-pin and the layout showed 16 pads, it reported a mismatch. I didn't agree with that measurement, because the data said it was wrong: layout footprints routinely have more pads than the component uses â€” extra pads for package variants, no-connect pins â€” so literal equality was generating false alarms on real boards.

So I pushed back the only way that counts: with evidence. I pulled 20 BOMs that had pin-count mismatches and sorted them into three buckets â€” footprint larger than the component, footprint smaller, and exact match. The pattern was clean. Footprint-larger was almost always a legitimate package variation; footprint-smaller was a genuine mismatch, because the part physically can't fit; exact match was fine. Now I had a rule I could defend with numbers instead of a preference.

Then the part that maps to your question. I couldn't just delete pin count from the comparison â€” it's the signal that catches a wrong part, and the requirement was to fix the false alarms without breaking genuine mismatch detection. I had my reservations about pin count as a signal; I've said since that the better signal is the reference designator combined with the footprint name. But I committed to the direction: keep pin count in, and make it discriminating. If the layout has more pads, flag it for review instead of calling it a mismatch. If it has fewer, call it a definite mismatch. That opened a new hole â€” a larger footprint on the wrong component type â€” so I added a component-type check with a configurable pin-count ratio threshold, defaulted from the data at 2:1.

I owned the downside instead of hiding it. A heuristic can still miss a genuine mismatch that happens to pass the type and ratio rules, so I built a debug view that shows the raw BOM and layout values and the tool's decision for every component, and lets the engineer override it. The result: false positives dropped from about 12% to under 2% on boards with mixed component types.

**A:** Because pin count isn't a clean signal. A footprint is designed for a whole package family; an 8-pin SOIC footprint can host a 4-pin network with four no-connect pins.
