# Q35 — a time when you worked on something outside your comfort zone

**Mapped LP(s):** Learn and Be Curious.

**Story used:** Tab Scroller (Chrome extension, Manifest V3) — moving from single-document deterministic tools into an event-driven service-worker architecture with an LLM in the command path (`manifest.json`; `EXTENSION_SUMMARY.md`; `PRD.md`; `IMPLEMENTATION_GUIDE.md`; `10_project.md`; `progress.txt`). Deliberately a **different axis of discomfort** from Q21, which was learning new vision math and libraries (OpenCV.js / TensorFlow.js / TPS from the Bookstein paper). Here the unfamiliar things are (a) a stateless, restartable extension execution model and (b) a probabilistic model whose output is a destructive browser action.

## Answer (core, ~470 words)

The discomfort I'll give you is a different kind than learning a new library. The tools I'd built before were single, self-contained pages — one document, one context, deterministic in and deterministic out. Tab Scroller is a Manifest V3 extension, and it broke both of those assumptions at once.

First, the execution model. An MV3 extension isn't a page. It's a background service worker the browser can tear down between events, content scripts injected into arbitrary pages, and message passing between them. There's no long-lived state to lean on. I built tab snoozing around `chrome.alarms` on a one-minute tick and `chrome.storage.local` holding the snoozed tabs as `{url, title, wakeTime}`, re-opening them as inactive background tabs when the time comes — so it survives a browser restart. That forced me to design for the possibility that my code simply isn't running when I need it, which was the opposite of the mental model I had.

Second — and this is the part that actually made me uncomfortable — the AI command layer puts a probabilistic model in the control path. The layer maps a natural-language command to a browser action: group, close, bookmark, pin, mute, reload, sort, snooze, search. It runs on Gemini and Ollama, with intent recognition and tool-calling. The output of that system isn't a number on a screen; it can close a user's tabs. A confident wrong answer is destructive. I'd never built anything where the model's failure mode was that concrete.

My response was to constrain it rather than trust it. Simple commands are handled locally by rules and never reach the API at all — "close all youtube tabs" doesn't need a language model. Before anything is extracted, a pre-filter trims the tab set by domain category and keyword, and metadata extraction runs in parallel batches instead of one tab at a time. So the model only sees a reduced, relevant context, and the cheap deterministic path is the default. I also tried both ends of the model spectrum — cloud Gemini and local Ollama — because I wanted to see where the fallback line should sit, not just assume it.

The honest gap: I shipped the action layer without the guardrails I would want. I designed a confidence gate afterward — auto-execute above a threshold, confirm in the middle band, ask a clarifying question below it — plus transactional undo for closes and basic telemetry. That design is on paper, not in the build, and I say that plainly rather than dress it up. What I took from all of it is the lesson I carry forward: when a model is in the control path, the work isn't prompt tuning. It's building the deterministic envelope around the model — local fast paths, narrow context, and a way to take an action back.

## Deep follow-ups (likely bar-raiser probes)

**Q: What was actually hard about MV3 compared to a normal web page?**
**A:** The lifecycle. There's no guaranteed long-running process — the service worker can be shut down between events, so anything that must happen later has to be owned by the platform, not by a variable in memory. That's why snoozing is built on `chrome.alarms` ticking every minute and `chrome.storage.local` rather than a timer or an in-memory queue. The design question shifted from "what's my state" to "who wakes me up, and what has to be on disk before I stop running."

**Q: Why put an LLM in the control path at all — why not stick to rules?**
**A:** Because the useful requests are open-ended — "group my travel research," "close the tabs I haven't touched in an hour" — and hardcoding every phrasing is linear effort on an unbounded input space. But I kept the deterministic path as the default: simple, pattern-matchable commands are resolved locally with rules and never hit a model. The LLM handles the residual, not the common case.

**Q: How do you stop the AI from doing something destructive?**
**A:** Two layers. The cheap one is routing: simple commands stay local, and the model only sees a pre-filtered, relevant slice of tabs, so the blast radius is smaller by construction. The stronger layer — a confidence gate with confirmation, transactional undo for closes, and telemetry — I designed but did not ship. I'd rather state that gap than imply protection that isn't in the build.

**Q: How do you keep the AI fast and cheap?**
**A:** Reduce what the model sees and how often it's called. Rule-based shortcuts handle the common cases with zero API calls; the pre-filter narrows the tab set by domain category and keyword before extraction; metadata is pulled in parallel batches rather than sequentially; and content is compressed into compact triplets instead of raw page text. The goal is that the model is the last resort, not the first hop.

**Q: Did you look at local models, or only cloud?**
**A:** Both. The extension supports cloud Gemini and local Ollama, and the reason to carry both is the same reason I built the rule path: I wanted a fallback that doesn't depend on a provider being reachable or on sending the user's tab data off the machine. Which one runs is a settings choice, not a rewrite.

**Q: What would you do differently?**
**A:** Ship the guardrails with the action layer, not after it. Specifically, the confidence gate and undo should have landed together with tool-calling, because the moment destructive actions become model-selected, confirmation and reversal are part of the feature, not polish.
